# Dark mode (desktop) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dark theme for the whole desktop app on the existing token names, a System / Light / Dark preference in Settings → General stored in the profile and mirrored on the device, applied before the first paint, with the dark token set documented for the mobile app.

**Architecture:** One `:root[data-theme="dark"]` value block next to the light `:root` block in `src/index.css` and `docs/design-system/tokens.css`; a blocking `public/theme-boot.js` stamps `data-theme` before paint; `ThemeProvider` resolves the preference (device mirror, then profile), follows the OS under System, resets the chart token cache and drives the Tauri window theme; the few raw literals left in components and the style guide become tokens first, so the light theme stays as it is.

**Tech Stack:** React 19 + TypeScript, Tailwind (token names), CSS custom properties, Vitest (node environment, `node:vm` for the boot script), Tauri 2.12 (`@tauri-apps/api` window/webviewWindow), Rust + rusqlite (migration 022), i18next (ten locales).

**Spec:** `docs/specs/2026-10-16-dark-mode-design.md` (D1–D16, token table §4.1, validation §4.2, rules §4.3, literal list §4.4, storage §4.5, runtime §4.6, settings §4.7, docs §4.8). The prototype `docs/specs/2026-10-16-dark-mode-prototype.html` carries the same dark block; copy values from the spec table, never retype them from memory.

## Review Focus

1. `localStorage['moony-theme']` holds garbage (`"blue"`, `""`) or the storage throws (blocked site data): the app must resolve System and never fail to render. → Task 4 tests `readStoredPreference` and the boot script with a throwing storage.
2. The OS switches appearance while the preference is System: the app repaints live; while it is Light or Dark: nothing changes. → Task 4 tests `resolveTheme`; Task 5 wires `setTheme(null)` under System; manual check in Task 10.
3. The profile says `dark` (set on another machine) and the device mirror says `light`: after unlock the profile wins and the mirror is rewritten, with no flicker back on the next click (the sync effect depends on `user?.theme` only). → Task 9 implements it; Task 10 verifies by editing the mirror before unlock.
4. The save of the preference fails (`validation.themeInvalid` or a locked database): the UI reverts to the previous theme and shows the error toast. → Task 8 tests the Rust rejection; Task 9 wires the revert.
5. A chart whose series colors are memoised on its own inputs (`PerformanceChart.colors`) keeps stale hex after a switch. → Task 6 adds the theme version to the memo; Task 10 checks Stocks analysis after a switch.

```ts
import { readFileSync } from 'node:fs';
import { describe, expect, it } from 'vitest';

const INDEX = readFileSync(new URL('./index.css', import.meta.url), 'utf8');
const TOKENS = readFileSync(new URL('../docs/design-system/tokens.css', import.meta.url), 'utf8');
/** Theme-independent names, plus the two gradients that follow `--dark-hi/lo` through var(). */
const THEME_FREE = /^--(r-|fs-|fw-|ls-|sp-|font$|dark-grad|sidebar-w$|page-|control-h|input-h$|nav-row-h$|table-row-h$|t-fast$|t-base$|ease$)/;

function block(css: string, selector: string): Map<string, string> {
  const start = css.indexOf(selector + ' {');
  expect(start, `${selector} block`).toBeGreaterThanOrEqual(0);
  const body = css.slice(start, css.indexOf('\n}', start));
  const out = new Map<string, string>();
  for (const m of body.matchAll(/(--[\w-]+)\s*:\s*([^;]+);/g)) out.set(m[1], normalize(m[2]));
  return out;
}
function normalize(v: string) {
  return v.replace(/\s+/g, ' ').replace(/'/g, '"').replace(/\b0\.(\d*?)0+\b/g, '0.$1').replace(/\b(\d)\.0\b/g, '$1').trim();
}

describe('theme token blocks', () => {
  it('the dark block declares exactly the themed names of the light block', () => {
    const light = [...block(INDEX, ':root').keys()].filter((n) => !THEME_FREE.test(n));
    const dark = [...block(INDEX, ':root[data-theme="dark"]').keys()];
    expect(dark.sort()).toEqual(light.sort());
  });
  it('tokens.css carries the same declarations as index.css in both blocks', () => {
    for (const sel of [':root', ':root[data-theme="dark"]']) {
      const app = block(INDEX, sel);
      const doc = block(TOKENS, sel);
      for (const [name, value] of app) {
        if (sel === ':root' && name === '--font') continue; // CJK fallbacks differ by design
        expect(doc.get(name), `${sel} ${name}`).toBe(value);
      }
    }
  });
  it('the dark root switches native controls', () => {
    expect(block(INDEX, ':root[data-theme="dark"]').size).toBeGreaterThan(50);
    expect(INDEX).toMatch(/:root\[data-theme="dark"\] \{\s*color-scheme: dark;/);
  });
});
```

```ts
const SRC = readFileSync(new URL('./theme-boot.js', import.meta.url), 'utf8');
function boot(stored: string | null | (() => never), systemDark: boolean) {
  const attrs: Record<string, string> = {};
  const ctx = {
    localStorage: { getItem: typeof stored === 'function' ? stored : () => stored },

  return attrs['data-theme'];
}

it('follows the OS for a missing or unknown key', () => { expect(boot(null, true)).toBe('dark'); expect(boot('blue', false)).toBe('light'); });
```
