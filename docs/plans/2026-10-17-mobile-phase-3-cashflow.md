# Mobile Cashflow tab with budgets (Phase 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The phone's Cashflow tab (spec §8.7): the actual income and expenses of a month, quarter or year with the Úspora hero, the twelve-month bars, category rows that carry their budget limit as a bar, the pushed list of a category's transactions with recategorize, and the pushed "Spravovat rozpočty" page with the limit sheet — on the existing Tauri commands, without any Rust change.

**Architecture:** Three pages under `src/mobile/pages/` on the Phase 1 shell (`Screen`, `NavBar`, `EntityRow`, `StatRow`, `Sheet`, `AmountField`), fed by the two report commands the desktop pages already call (`get_cashflow_actuals` for the rows, bars and totals; `get_budgeting_report` for the limit of each category) and the budgeting commands (`get_budget_goal_history`, `upsert_budget_goal`, `delete_budget_goal`, `delete_budget_goal_intervals`). The selected period and account scope live in the Cashflow route's query string, so the pushed pages return to the same period and Android back never walks through months. Every pure decision (query-string state, row models, budget rows, the limit form's validation, drilldown rows) lives in `src/mobile/lib/*.ts` with Vitest tests; components only render; the budget version arithmetic is the desktop's `src/utils/budget-goal-versions.ts`, reused as is. Writes go through the desktop's `useSaveBudgetGoal` / `useDeleteBudget` / `useDeleteBudgetIntervals` hooks and `refreshMoneyFlows` (AGENTS rule 7).

**Tech Stack:** React 19, TypeScript, wouter (`useSearch`, `useParams`), TanStack Query, Radix (Dialog as the sheet, DropdownMenu as the context menu, ToggleGroup as the segment, Checkbox), Recharts for the bars, Lucide, react-i18next (`mobile` namespace, ten locales), Tailwind on the design tokens.

**Spec:** `docs/specs/2026-10-16-mobile-app-design.md` §8.7 (binding; §4 principles, §10.3–10.5 components, §7 disposition "Rozpočty merged into Cashflow", "Plánování cashflow v2"); prototype `docs/specs/2026-10-16-mobile-app-prototype.html` frame 09 and note 13 (the spec wins where they differ, ruling R7 of Phase 1); the phone component contract `docs/design-system/mobile.css` + `mobile.html` + `docs/design-system/README.md` §13. Parent plan: `docs/plans/2026-10-16-mobile-app.md` (Phase 3 outline). Out of scope: Plánování cashflow (v2), Export (needs the share sheet, Phase 5), any Rust change, the desktop pages.

## Review Focus

Inputs the spec implies and no task's tests exercise directly; each line's test is pinned to the owning task.

1. **A limit in another currency than the report** (a EUR limit, a CZK report): the row's sub-line shows the limit in EUR with its ISO code and the bar uses the backend's `budgetPercentage`; the CZK spend is never compared 1:1 with the EUR limit — Task 1, `categoryRows` test with `budgetCurrency: 'EUR'`.
2. **The current month on its first day, nothing booked yet**: the period bar and the twelve bars stay on screen, the empty state names the period, the previous month is one tap away — Task 1, `barsFor` test (every month outside the period muted, the empty current month included); Task 2's empty branch on the simulator.
3. **Hidden amounts**: the hero, both stats, every row value, the limit amounts in sub-lines, the bars' value axis, the summary line's nothing (counts stay), the drilldown amounts and the budgets page's limits all mask; counts and percentages stay visible — Tasks 2, 3, 5 on the simulator with the eye toggled (the helpers keep numbers, components format through `useMoneyText`).
4. **A budget whose only interval has run out, next to one that starts next month**: the ended one is listed last, dimmed, without "Smazat interval"; the scheduled one shows "Naplánováno" and its start month — Task 5, `budgetRows` tests.
5. **Saving a limit over an existing one**: the first tap lists what it replaces and saves nothing, the second saves; a save that changes nothing says so and closes — Task 4, `limitFormState` and `limitSaveLabel` tests (collisions through the desktop's `overwrittenPeriods`), then on the simulator.

## As built / rulings

Rulings taken while writing and executing this plan (spec §8.7 is the authority; each line says what was decided and what it costs if wrong). Numbered R1… so the hand-over can cite them; the list grows during execution.

1. **Period and scope live in the Cashflow route's query string** (`?tf=&o=&acc=`, replaced not pushed): the pushed drilldown and budgets pages return to the same period and Android back is not a tour of months. Cost: a deep link to `/cashflow` opens the current month.
2. **The tab opens on the current period**, as the spec's "‹ Říjen 2026 ›" and the desktop Cashflow report do — not on the month of the newest transaction (the desktop Budgets page's rule). Cost: on the first days of a month the first screen is an empty period with the bars and ‹ one tap away.
3. **The Úspora hero has no chart and no segment** (prototype frame 09: the period controls sit above it), so Phase 1's `Hero` is not reused; `CashflowHero` implements the contract's `.m-card--hero` subset. Follow-up: extract a shared `HeroCard` once a third hero without a chart appears.
4. **A bar tap switches the period to that month** (spec item 2) and there is no callout: the hero and stats rewrite instead. Twelve bars at 390 pt give 25 pt tap zones over the full 110 pt height, under the 28 pt mark rule of §10.4. Cost: a mis-tap lands on the neighbouring month, one more tap away.
5. **Category rows are `EntityRow`s with a new `bar` slot** (the row rule of README §13 names categories), not a second row component. Bars: share `s3`, limit `s1`, over `loss`; "blíží se" is written in the sub-line, never colour alone (the prototype's `--near` colour is dropped).
6. **The budget summary line is a link to Spravovat rozpočty**, the second way in besides `···` (§4 principle 2).
7. **Export is left out of `···`**: the phone has no share sheet or file save yet (Finance ruling, commit 7e00be95); spec §7 keeps CSV export "through the share sheet", which arrives with the backup work of Phase 5. Follow-up listed.
8. **"Výdaje bez limitu" on the budgets page is the six completed months' average** per category (one `get_budgeting_report` over `averageWindow()`, the same report the limit sheet's hint uses), not the current month — a month-old limit question deserves a monthly figure, and the first of a month would otherwise show nothing.
9. **"+ Přidat rozpočet" is one sheet with two steps** (pick the category, then the form), because this base's `useSheetHistory` holds one entry and two sheets opening in one commit would pop each other.
10. **Months are the platform's `<input type="month">`** (iOS and Android both show a wheel): §10.5's "inline compact picker" without a component of our own.
11. **The drilldown's tap, swipe and long press all change the category** through a thin `CashflowCategoryPickerSheet` (grouped list, no search, no recents, no learning): this base has neither the Finance branch's `CategoryPickerSheet` nor its `TransactionSheet`. Follow-up for the parent after the merge: swap in `CategoryPickerSheet` (search, recents, "Zapamatovat") and open the transaction sheet on tap.
12. **The drilldown lists 100 rows and a "Zobrazit dalších 100" button** (the desktop's page size) rather than an infinite list — a report line rarely has more, and the snapshot must not reshuffle.
13. **A partial period gets one caption** ("Období ještě neskončilo…") under the FX note; the backend reports no partial-month flag, so the period's end being ahead of now stands for it.
14. **An empty period keeps the period bar and the bars** so the previous month is one tap away; only a profile without any transaction gets the full empty state with "Otevřít Finance".
15. **Report-row menus on the Cashflow page** (long press: Zobrazit transakce, Upravit/Nastavit limit) mirror the desktop Budgets table's menu; swipes on report rows do nothing (no natural action).
16. **Unbudgeted rows on the budgets page are not tappable as a whole**: the small "Nastavit limit" button is the action (a button inside a button row is invalid HTML), the rest of the row is text.

Rulings taken during execution (2026-10-17, from the task reviews and the pane checks):

17. **The transfers section head carries no note** — "mimo příjmy a výdaje" truncated the title "Investice, spoření a převody" at every width; §8.7 item 5 names no note (it was the prototype's). Cost: the reader learns from the section's position that transfers are outside income and expenses.
18. **A limited row's sub-line is the spec's literal limit progress first** — "3 206 / 3 000 Kč" (loss-tinted when over), then the state word ("nad limitem" / "blíží se limitu"), then the count last, so an ellipsis drops the count and never the limit; share rows put the share first and the count last too. Cost: the prototype's "limit 8 000 Kč" wording goes.
19. **The accounts sheet edits a draft and applies it once on Hotovo**, after its history entry has settled (`afterHistorySettles`: one popstate or a 350 ms fallback); scrim, Escape and Android back discard the draft; Hotovo is disabled while nothing is selected. A live-applying sheet replaced its own history entry through wouter's `replaceState` and broke Android back. Cost: no live preview of the scope while the sheet is open.
20. **The pane at 390 × 844 is the verification evidence**, not the simulator's own screen: its webview instance stays on the lock page (the simulator-panel grant is missing), as in Finance 2a.
21. **A moved drilldown row's sub-line leads with "přesunuto"** so the end-truncating sub-line never hides the one non-colour signal. Cost: the day shifts right by one word on moved rows.
22. **Two accessibility strings beyond the brief**: `cashflow.picker.current` names the current category's check mark (`role="img"`), `cashflow.rowMenu` ("Další akce: {{title}}") replaces a hard-coded ": " in the row-menu trigger name.
23. **A field the person edits shows its value while amounts are hidden** (the limit field pre-filled on edit) — an input cannot be masked and typed at once; the hint and the boxes around it mask.
24. **The limit hint is `budgeting:readiness.observedAverage`** with the observed completed months, not `dialog.averageHint`'s fixed "last 6 months" (the average divides by the observed months). The two new validation keys were dropped for `common:validation.amountPositive` / `effectiveUntilBeforeStart`.
25. **Unbudgeted rows on the budgets page are Údržba-style action rows** (chip, title, sub, a 44 pt small button; contract `.m-row--act`), not `EntityRow`s — the row's truncating value slot would clip the button's hit area to 34 pt.
26. **Editing a budget from the budgets page opens on the current month** (`effectiveMonth` undefined → `defaultEditMonth`: the current month for active and ended budgets, the scheduled start for a scheduled one), as the desktop's manage dialog does, so a save never rewrites past months by default; the report's row menu keeps the shown period's start.
