# Report currencies and quiet financial UX

The user approved this architectural change on 2026-10-08: preserve native data, remove mandatory CZK semantics from reports, use the user's currency directly, and simplify currency commentary on Cashflow, Cashflow planning and Budgets. Autonomous implementation and testing are authorized; the earlier request waives intermediate approval questions.

## Meaning and scope

Native amounts, instrument quantities, account/contract currencies and transaction dates remain authoritative. A report has an explicit target currency; CZK may remain a reference quotation or a derived cache for existing portfolio/projection contracts. This change replaces the actual cashflow, budgeting, transaction drilldown and planned cashflow currency pipeline, including their MCP consumers. It does not rewrite stored transactions/goals or change investment pricing, tax accounting, legacy portfolio cache schemas or amortization units. Existing bank-import MCP work in dirty files belongs to another task and must be preserved.

An EUR transaction in an EUR report contributes its native amount even with no FX history. Different currencies use a ratio from a common valid historical rate date on/before booking, maximum ten-day lookback. Never combine rates from different dates or use today's rate for actuals. Currency codes are normalized/validated. Missing source or target rates exclude only affected contributions, retain native rows and explicitly mark incompleteness. Exact-match currencies need no rate, including supported profile currencies absent from the provider. SQL errors remain errors.

Actuals, comparisons, averages, category summaries and drilldowns share converted row contributions and target precision. Monetary response fields remain decimal TEXT. Rename unit-specific fields to signedAmount and budgetLimit; return reportCurrency on reports and drilldown rows. Round converted row contributions once at the currency's minor unit so visible detail and summaries reconcile; support zero-, two- and three-decimal currencies. No rounding in the intermediate reference currency. Preserve existing semantics of refunds, reversals, own-account transfers, pending exclusion, account scope, quality counts and zero-net groups.

Budget goal currency is part of the stored limit and stays unchanged when the profile currency changes. Version selection and original TEXT preservation remain intact. For display, each effective month's limit uses its own currency and the rate at that month's start, with the same historical policy. Same-currency limits require no rates. Unknown limit conversion keeps limit/percentage unavailable. Report totals and limits are in the report currency; historical suggestions must be requested in the goal editor's currency so examples and input unit agree.

Planning normalizes native annual/monthly items and converts them directly into the requested target using one current rate snapshot. Same-currency values bypass FX. Property cost collections may contain several currencies and must convert each component, never label a computed target amount as native CZK. Original amount/currency/frequency and replacements stay intact. Missing rates keep item/source visible with unavailable conversion and exclude it from numeric totals. Monthly/yearly totals, items and sections reconcile at target precision. Existing internal callers explicitly requesting legacy CZK may retain that unit; never relabel CZK values as another currency. MCP cashflow/budgeting use the profile currency inside the shared calculation and do not convert the result a second time.

## UI

The user's profile currency is the default reportCurrency and participates in query keys along with rate revision, range, scope and filters. A profile switch cannot render cached amounts with a different symbol. Format returned amounts directly using the response's currency; no CZK conversion in formatters, exports, chart labels or drilldowns. When the target is unsupported by FX, stay in that target: same-currency values still work and mixed-currency gaps are explicit.

Preserve the current Moony design system. Remove always-visible CZK/history/current-rate/unsupported-display explanations, routine rate dates, and repeated technical notes. Complete ordinary reports show no currency disclaimer block. Keep a compact, specific warning only for missing conversions, invalid data or unavailable budget limits; details belong next to the affected row or in an accessible disclosure. Show sample size near an average where useful, without repeating a full coverage paragraph on every page. Planning remains clearly monthly/yearly and an estimate through its title/short context; no persistent technical FX paragraph. Source amount/frequency remains available when useful to editing. Both cs/en updated.
